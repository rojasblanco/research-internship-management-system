# Guía operativa genérica

Esta guía describe el rol de una persona administradora del sistema. No sustituye políticas internas ni contiene instrucciones específicas para una persona concreta.

## Principio principal

El operador trabaja desde la **interfaz administrativa**. No debería abrir el editor de Apps Script ni ejecutar funciones manualmente para realizar cierres, generar reportes o mantener el flujo ordinario.

## Durante el ingreso

Desde el portal se revisan y registran, según permisos:

- estado de postulación;
- entrevista;
- fecha real de envío de cursos;
- progreso de cursos;
- formalización;
- documentación;
- carpeta personal;
- horario oficial y cambios registrados;
- extensión/retiro/transición cuando corresponda.

## Durante la pasantía

El sistema consolida Activity Planner, asistencia, horario y progreso. Los períodos intermedios se procesan automáticamente cuando sus datos son coherentes.

El operador interviene cuando el portal muestra una excepción o inconsistencia que impide el cierre automático.

## Informes

La sección de Reportes permite consultar el historial disponible por persona. Según permisos, el operador puede:

- abrir un reporte;
- descargar un artefacto disponible;
- revisar estado/fecha/versión;
- ver un error de generación;
- solicitar una regeneración controlada.

No es necesario generar manualmente cada reporte periódico.

## Cierre final

El cierre final requiere revisión humana autorizada. Antes de confirmar se revisa la trayectoria relevante, incluyendo horas, actividad, documentación, excepciones y reportes. Los documentos finales posteriores dependen de la política de la organización.

## Regla de seguridad

Si una acción no está disponible en el portal, no debe improvisarse modificando directamente tablas derivadas o ejecutando funciones en producción. Debe tratarse como una incidencia/mantenimiento del sistema.
